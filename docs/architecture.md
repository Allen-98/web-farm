# 架构与迁移

游戏使用 Phaser、TypeScript 和 Vite，规则层与渲染、输入、存储分开。

| 目录 | 职责 |
| --- | --- |
| `src/domain/` | 固定步长模拟、寻路、生产、销售、资金、解锁、员工调度与存档校验 |
| `src/content/` | 地图、三章设施与产能升级配置 |
| `src/rendering/` | Phaser 视图、程序绘制纹理、等距投影和镜头 |
| `src/input/` | 键盘、摇杆、点击与浏览地图的拖动输入 |
| `src/presentation/` | DOM HUD、经营面板与提示 |
| `src/platform/` | 浏览器存档与音效 |
| `tests/` | 交易、资源守恒、成长、自动化、迁移和镜头约束检查 |
| `verification/` | 自动生成的测试快照、生成器和关闭正式存档写入的开发试玩入口 |

`World` 保存位置、库存、员工任务、计时器、建设已付金额和统计，可以 JSON 序列化。模拟不依赖 Phaser 或 DOM，通过 `ScenePorts` 与视图交互。

每枚鸡蛋消耗一份玉米。包装消耗鸡蛋，烘焙消耗面粉和鸡蛋；资源转移和交易均校验容量与数量。存档校验检查原料、加工品、收入与建设支出的守恒关系。

镜头缩放和拖动属于表现层，不改变角色移动、互动距离或经济数值。

`domain/orders.ts` 保存订单序号、合同快照、已交货库存、备齐时间和累计结算记录。合同在承接时固定，之后开设新摊位不会改变已有订单。送货任务复用 `logistics.ts` 的来源、目的地、容量和其他员工预占批次；订单收货纳入每类货物的守恒校验，结算后计入累计交付量。限时使用模拟时间，备齐时间锁定加急奖金。

`domain/operations.ts` 定义七处设施与两档速度升级。所有加工和销售计时统一读取 `cycleSeconds`，升级将当前计时按新旧周期比例缩放，避免额外产物或进度丢失。设施状态由实际库存和开工条件派生，DOM 面板和 Phaser 标签读取相同数据。原料配方不随提速变化。

`farm-v3.2` 在验证旧版资源账目后增加空订单状态与未购买的提速节点，保留资金、库存、雇员和原有投资。浏览器适配层先备份旧原文再写新记录；读取失败时禁止覆盖原存档。后续 Unity 移植可逐项重写这些引擎无关规则与对应测试场景。

`domain/dispatch.ts` 在 `World.dispatch` 中保存策略、保底数量、员工分工和实际预留量。区域按交货地点划分，专岗限定于员工原有技能。`logistics.ts` 统一比较保底缺口、策略、目标库存和其他员工的承诺量，领取时同时受来源可用量和目标余量限制。未装货员工可重新调度，在途员工完成既定任务；目标失效时将原货物送回来源。预留量不计入经济库存，只有真实转移才改变资源账目。

推车使用追加的建设节点记录购买款项，不改变旧节点顺序。`workerCapacity` 和员工更新共同读取推车等级，分别控制真实容量、搬运批次、移动与装卸。Phaser 根据同一等级绘制推车，货物图层封顶并显示实际数量，不参与规则计算。

`domain/telemetry.ts` 按模拟秒保留最多 60 个样本，使用前后累计计数之差统计实际货流、收入与作业批次。供料条件和仓满条件分别累积等待时间；设施只从已建设后的时间开始计入开工率。面板和后台暂停模拟，不计入等待。面板内领取的订单收入先进入待计入项，报表立即可见，下一次模拟合并进当前样本，不重复计算。瓶颈建议结合历史等待与当前上游库存派生，不修改生产状态。

`farm-v3.3` 先按旧版规则验证 v3.2 存档，再增加默认调度、空统计和未购买推车节点，保留已有合同、货物、员工任务和所有经济进度。旧任务首次运行时由调度器接续；运输预留和统计状态可序列化与验证。DOM 管理面板调用领域命令，规则层继续不依赖 Phaser、DOM 或浏览器存储。

迁移 Unity 时可复用数据配置和回放场景，将模拟规则改写为 C#，用 Unity 视图及 UGUI 替换 Phaser 和 DOM。微信端需要额外的运行环境适配。当前仓库没有 Unity 工程，也未完成微信真机适配。
